# 🌊 Route Traffic Manager

Скрипт от **WieldVPN** для переадресации TCP/UDP-трафика и настройки промежуточных серверов на Debian и Ubuntu.

Подходит для AmneziaWG, WireGuard, VLESS и XRay.

![Bash](https://img.shields.io/badge/Language-Bash-green)
![System](https://img.shields.io/badge/OS-Ubuntu%20%7C%20Debian-orange)

## Возможности

- Несколько направлений на разных портах.
- Имена маршрутов и объединение в группы.
- Переключение одного маршрута, группы или всех направлений на другой hop.
- Экспорт и импорт конфигурации для быстрой подготовки нового сервера.
- Сохранение правил после перезагрузки.
- Интерактивное меню для настройки и управления.

## Установка

На сервере с Debian/Ubuntu выполните от `root`:

```bash
wget -O routing.sh https://raw.githubusercontent.com/GRTUBORG/routing/refs/heads/master/routing.sh && chmod +x routing.sh && ./routing.sh
```

Для повторного запуска меню:

```bash
./routing.sh
```

Перед обновлением сохраните текущий файл:

```bash
cp -a routing.sh "routing.sh.bak.$(date +%Y%m%d-%H%M%S)"
```

## Перенос на новый hop

Экспортируйте конфигурацию с действующего **second-hop**, который направляет трафик к конечным серверам.

**1. На действующем hop:**

```bash
./routing.sh export-config /root/hop-config.tar.gz
scp /root/hop-config.tar.gz root@NEW_HOP_IP:/root/
scp ./routing.sh root@NEW_HOP_IP:/root/
```

Замените `NEW_HOP_IP` адресом нового сервера. Для экспорта нужен Python 3: если он отсутствует, установите `apt-get update && apt-get install -y python3`.

**2. На новом чистом сервере:**

```bash
chmod +x /root/routing.sh
/root/routing.sh import-config /root/hop-config.tar.gz
```

Импорт установит недостающие зависимости, восстановит маршруты, имена и группы, включит forwarding и сохранит правила. Для автоматической подготовки нужен Debian/Ubuntu с systemd.

**3. Проверьте работу реального клиента через новый hop**, затем укажите его как резервный в своём watchdog. Доступность SSH сама по себе не подтверждает работу VPN.

Экспорт и импорт также доступны в пунктах **11** и **12** меню.

## Переключение направлений

На входном сервере:

```bash
# Переключить все маршруты с OLD_IP на NEW_IP
./routing.sh replace-hop OLD_IP NEW_IP

# Переключить только маршруты группы HOP-A
./routing.sh replace-group HOP-A OLD_IP NEW_IP
```

Порты, имена и группы сохраняются. Watchdog устанавливается отдельно и может использовать эти команды для автоматического переключения.

## Дополнительные команды

```bash
# Проверить импорт без применения и установки зависимостей
./routing.sh import-config /root/hop-config.tar.gz --dry-run

# Импортировать без автоматической установки зависимостей
./routing.sh import-config /root/hop-config.tar.gz --no-install-deps

# Восстановить только имена и группы для уже существующих маршрутов
./routing.sh import-metadata /root/hop-config.tar.gz

# Справка
./routing.sh --help
```

`import-metadata` проверяет совпадение маршрутов с bundle, создаёт backup БД и восстанавливает недостающие имена и группы. Правила firewall не меняются. Если уже задано другое имя или группа, команда сообщит о конфликте. Для проверки без записи добавьте `--dry-run`.

## Что важно знать

- Импорт предназначен для чистого hop. Если уже настроены NAT/FORWARD или есть маршруты в БД, скрипт откажется их перезаписывать. Переходы в пустые стандартные цепочки выключенного UFW не мешают импорту и сохраняются.
- INPUT/OUTPUT старого сервера не переносятся. Перед импортом создаётся backup в `/var/backups/routing-import/`; при ошибке применения выполняется откат.
- Поддерживаются простые IPv4 TCP/UDP-маршруты с одиночными портами. Нестандартные правила могут потребовать ручной настройки.
- Облачный firewall, приватные маршруты, VPN-интерфейсы и настройки watchdog нужно подготовить отдельно.
- Не меняйте firewall параллельно с импортом или переключением. Если скрипт занят другой операцией, дождитесь её завершения.
